Um aluno de Engenharia Informática cola o enunciado do Trabalho Prático 2 no assistente de IA. Dez segundos depois tem Aluno.java, Turma.java e Main.java, a compilar e prontos a entregar. Três semanas depois está sozinho na defesa oral, diante de um docente que lhe pergunta porque é que o ArrayList guarda objetos e não números soltos. E não sabe responder.

O problema não é a IA ser má a programar. É ser boa demais a fazer o trabalho de quem devia estar a aprender. Construí o Hint Ladder para inverter isso: um plugin do Claude Code que ensina todas as cadeiras do curso, dá feedback ao código, ao processo e às ideias do aluno, vigia o Moodle por ele e, em trabalho avaliado, se recusa a entregar a solução.

I. O problema que ninguém mede

Toda a gente tem uma opinião sobre a IA na universidade. Quase ninguém tem números. Por isso comecei pelo teste mais simples: o mesmo pedido, o mesmo modelo, duas pastas vazias. Numa, o Claude Code sozinho. Na outra, o Claude Code com o Hint Ladder.

Depois repeti a experiência de forma sistemática, com o avaliador do próprio Claude Code (claude plugin eval): 12 casos de trabalhos avaliados (um por especialista de linguagem, um enunciado em português sem a palavra "avaliado", um aluno que insiste, uma pasta onde só os ficheiros dizem que é avaliado, uma apresentação avaliada), duas execuções por caso, com e sem o plugin, no mesmo modelo. Sem regras, o modelo entregou o trabalho três vezes em cada quatro. Com o Hint Ladder, nunca, e continuou a ensinar em todas as respostas.

II. Sobe a escada tu mesmo

O nome vem do mecanismo central. Em trabalho avaliado, o tutor sobe uma escada de pistas, um degrau de cada vez, e só quando o aluno já tentou e continua encravado. Experimenta com o mesmo enunciado do teste acima:

:: o enunciado · Trabalho Prático 2 · vale 4 dos 20 valores

Implementa em Java uma classe Turma que guarda alunos (número, nome, nota) num ArrayList, com métodos para adicionar um aluno, calcular a média das notas e devolver o aluno com a nota mais alta.

resposta real do Hint Ladder

Este trabalho conta para a nota (vale 4/20, entrega no Moodle), por isso não posso simplesmente entregar-te a classe Turma já feita — no dia da defesa oral ou do exame vais precisar de saber explicar e escrever isto sozinho. Posso ajudar-te a chegar lá, passo a passo.

Vamos começar pelo básico: explica-me por palavras tuas o que o enunciado te está a pedir, especificamente:

  1. Que dados guarda cada aluno (número, nome, nota) — achas que isso deve ser uma classe Aluno à parte, ou achas que dá para meter tudo dentro da Turma?
  2. O que é que o ArrayList vai guardar exatamente?
  3. Para calcular a média, o que precisas de percorrer e o que precisas de somar?
ilustrativo · segue as regras do tutor

O que está em jogo aqui tem dois nomes: composição (uma Turma tem vários Aluno, e cada aluno é um objeto com os seus próprios campos) e percorrer uma coleção para a resumir (a média e o máximo saem de um único ciclo sobre o ArrayList). Está nos slides da cadeira sobre classes e objetos, e nos de coleções: ArrayList e o ciclo for sobre os seus elementos.

Antes de escreveres código: desenha num papel uma Turma com três alunos. O que está dentro do ArrayList, números ou objetos?

ilustrativo · compilado e executado

Um problema diferente, resolvido por inteiro com a mesma técnica: uma Playlist que guarda músicas e calcula a duração média e a música mais longa.

public class Playlist {
    private final ArrayList<Musica> musicas = new ArrayList<>();

    public void adicionar(Musica m) {
        musicas.add(m);
    }

    public double duracaoMedia() {
        if (musicas.isEmpty()) {
            return 0;               // uma playlist vazia não tem média
        }
        int total = 0;
        for (Musica m : musicas) {
            total += m.getSegundos();
        }
        return (double) total / musicas.size();   // divisão real, não inteira
    }

    public Musica maisLonga() {
        Musica maior = null;
        for (Musica m : musicas) {
            if (maior == null || m.getSegundos() > maior.getSegundos()) {
                maior = m;
            }
        }
        return maior;
    }
}

Com 95, 240 e 130 segundos, duracaoMedia() devolve 155.0 e maisLonga() devolve "Fado". Agora: que partes da Turma seguem este padrão, e o que muda?

Não há degrau 6. A solução avaliada é sempre escrita pelo aluno.

Cada ajuda fica registada num AI-USE.md, com a data e o degrau, para o aluno declarar o uso de IA com honestidade. Se o docente publicar um COURSE-POLICY.md com as regras da cadeira, o tutor obedece-lhe acima de tudo o resto.

III. Um semestre com o Hint Ladder

Um curso de Engenharia Informática não é uma disciplina, são trinta. Bases de Dados pede SQL Server, Sistemas Operativos pede C e shell, Matemática Discreta não tem código nenhum. Um tutor genérico serve mal todas, por isso o Hint Ladder tem um especialista por cadeira e poucos comandos para decorar:

  1. /setup
    Uma vez por ano. Colas as unidades curriculares do portal da escola. O Hint Ladder deduz a linguagem de cada uma, pergunta só o que é ambíguo e cria uma pasta por cadeira, cada uma com o seu especialista (java-expert, c-expert, sql-expert e mais sete). Uma cadeira sem especialista (C++ com OpenGL, Haskell, MATLAB) passa por uma entrevista de cinco perguntas e ganha um gerado de raiz.
  2. /go
    Todos os dias. O único comando a decorar: vê onde estás e arranca o que faz sentido, da revisão de hoje a um exame simulado quando o exame está perto.
  3. /lesson · /slides
    Para estudar. Aulas de dez minutos com exercícios que se corrigem sozinhos, e slides que se revelam passo a passo, com notas para estudar sozinho.
  4. /progress · /research
    Todas as semanas. Onde estás em cada cadeira, e depois pacotes de estudo sobre os temas fracos, com exemplos que mudam de domínio para nunca resolverem um trabalho avaliado em aberto.
  5. /moodle
    Sempre que um docente publica alguma coisa. Slides novos, um anúncio, um prazo que mudou: chegam até ti sem ires ao Moodle (secção VI).

V. Especialistas que conhecem os erros clássicos

Um bom professor de programação não diz "o teu código está errado". Reconhece o erro, porque já o viu cem vezes, e faz a pergunta que leva o aluno a encontrá-lo sozinho. Cada especialista tem um catálogo dos erros comuns da sua linguagem, cada um com a pergunta certa e um exercício que corrige a ideia. Em SQL, perante um LEFT JOIN com WHERE o.Status = 'paid' que faz desaparecer os clientes sem encomendas, o especialista não reescreve a consulta: nomeia o erro (MISTAKE-4) e pergunta, em substância, que valor tem o.Status na linha que o LEFT JOIN acrescentou.

VI. O Moodle vem ter contigo

A parte mais aborrecida de estudar não é estudar: é andar atrás da informação. O docente publica os slides da semana às 23h, adia o teste num anúncio, mexe no prazo de um trabalho, e o aluno só dá por isso tarde demais. O Hint Ladder passa a vigiar o Moodle por ele, com três regras não negociáveis: a chave do Moodle é escrita pelo aluno no seu próprio terminal e nunca passa pela conversa; os ficheiros dos docentes ficam só no computador dele; e nada do que vem do Moodle é tratado como uma instrução.

1

O docente publica

Slides da semana 2 sobre normalização, um anúncio a adiar o Teste 1, um prazo do TP1 que muda.

2

O computador avisa

Hint Ladder Moodle · bases-de-dados-1 1 ficheiro novo, 1 anúncio, 1 prazo alterado. Abre o Claude Code no curso e escreve /moodle.

Uma verificação de hora a hora, feita pelo computador, sem gastar o plano do Claude.

3

O Claude conta-te logo à entrada

> Olá! O que devo estudar hoje?

Olá! Há novidades no Moodle de Bases de Dados 1: o Teste 1 foi adiado para 14 de outubro, e o prazo do TP1 (consultas à base de dados Biblioteca) mudou para 16 de outubro. Também há um novo PDF sobre normalização.

Queres que eu use /moodle para descarregar e resumir isso, e atualizar as datas?

4

O /moodle trata do resto

Descarrega o PDF, escreve apontamentos com a página de cada conceito, mostra as duas datas que mudaram e só as altera depois de o aluno dizer que sim. No fim, sugere o próximo passo: uma aula de dez minutos sobre normalização, antes do teste.

Os textos dos passos 2 e 3 são saídas reais de um teste de ponta a ponta contra um Moodle simulado, porque os Moodles das escolas não se alcançam da máquina de testes. O próximo passo é testá-lo em escolas reais.

VII. Medir em vez de prometer

Construir um tutor de IA é fácil. Saber se ele faz o que promete é outra coisa. Três lições deste projeto:

Os números só valem se vierem de execuções reais. Todos os números deste artigo e do repositório saem de corridas do avaliador, com data e custo: a corrida completa custou 10,96 USD e a dos especialistas 3,90 USD. As amostras são pequenas (duas execuções por braço, num só modelo) e isso está escrito ao lado de cada tabela.

Os testes encontram o que os olhos não veem. Numa corrida, o especialista escrevia a tabela certa, mas o assistente principal resumia-a e deitava fora os nomes dos erros; o problema estava no teste, não no especialista. Noutra, algumas respostas a um curso em português vinham, no todo ou em parte, em inglês. Cada falha virou uma regra no plugin e um teste que a apanha.

As falhas publicam-se. No gráfico acima, as duas execuções de Java gastaram as voltas sem nomear o erro comum, e o juiz reprovou uma de Linux. Estão contadas como falhas, mesmo com uma repetição do caso de Java a passar em tudo. Um projeto que só mostra vitórias não merece confiança.

VIII. Para docentes: recomendar em vez de proibir

A reação natural de uma universidade à IA generativa é proibi-la. O problema é que a proibição não se consegue fiscalizar e empurra o uso para a sombra. O Hint Ladder foi desenhado para ser algo que um docente pode recomendar:

  • pistas em vez de soluções, por omissão, em qualquer trabalho avaliado;
  • um registo AI-USE.md por trabalho, que o aluno pode anexar à entrega;
  • um COURSE-POLICY.md que o docente publica e que o tutor segue à letra: proibir IA na cadeira, permitir código gerado, ou qualquer meio-termo.

Tudo corre no computador do aluno, nas pastas dele. O plugin não tem telemetria e não envia nada a ninguém.

IX. Experimentar

O Hint Ladder é gratuito e open source (licença MIT). Precisa do Claude Code e de um plano pago do Claude. Num terminal:

claude plugin marketplace add Steve45Green/hint-ladder
claude plugin install hint-ladder@hint-ladder

Depois, /setup uma vez e /go todos os dias. O código, os tutoriais passo a passo (em português e em inglês) e todos os resultados dos testes estão em github.com/Steve45Green/hint-ladder.

A IA não vai sair da universidade. A pergunta é se fica do lado de quem aprende ou do lado de quem entrega. O Hint Ladder é a minha resposta: aprende tu, não delegues.
